# 휴관일 달력 설계

- 날짜: 2026-09-08
- 범위: 백엔드 수집 게이트, 프론트 휴관일 화면, 과거 데이터 정리
- 배경이 된 두 `ponytail:` 주석: `backend/app/collector.py` `_VENUE_CLOSED_DAYS`,
  `frontend/src/lib/mmcaBusinessHours.ts` `VENUE_CLOSED_DAYS` — 둘 다 "요일만
  본다. 공휴일 달력이 들어오면 함께 고친다" 로 끝난다. 이 문서가 그 달력이다.

## 설명

지금 휴관 판정은 **요일 하나**다. 과천관·덕수궁관은 월요일, 서울관과
국립중앙박물관은 없음. 그래서 세 가지가 틀린다.

### 1. 공휴일 월요일에 문을 여는데 하루치를 통째로 버린다

2026-08-17 은 광복절 대체공휴일 월요일이었다. 과천관은 **열었다**.

| 날짜 | 요일 | 과천 non-여유 판독 | 서울 non-여유 |
|---|---|---|---|
| 2026-08-17 | 월 (광복절 대체) | **185** | 117 |
| 2026-08-18 | 화 | **0** / 219 | 65 |

그날 데이터가 남아 있는 것은 `_is_venue_open` 게이트가 그 데이터보다 나중에
생겼기 때문이다(`scripts/purge_out_of_hours_mmca.py` 의 docstring 이 같은 사실을
적어 두고 있다). 게이트가 있는 지금은 같은 날이 오면 **한 판독도 받지 않는다.**

### 2. 대체 휴관일에 빈 건물을 수집한다

위 표의 8/18 이 그것이다. 219 판독 전부가 여유였고, 과천관의 다른 모든
화요일은 non-여유가 59~157 이다.

```
2026-07-28  108      2026-08-18    0   ← 대체 휴관
2026-08-04  157      2026-08-25   65
2026-08-11   94      2026-09-01   59
```

빈 건물은 오류가 아니라 정상 200 응답 "여유" 로 온다. `build_profile` 이
(방, 요일, 시각) 평균을 내므로 그 하루가 화요일 셀을 그대로 끌어내린다.
`PROFILE_WINDOW_DAYS = 14` 에 요일당 두 날이 들어가므로, 창 안에 있는 동안
그 셀의 **절반**이 빈 건물이다.

### 3. 달력 휴관일과 임시 휴관일에는 로직이 아예 없다

`frontend/src/venues.ts` 의 `info.closedDays` 는 관 정보 표에 실리는 **문자열**
이고 어떤 판정에도 쓰이지 않는다. 1월 1일에도, 설날에도 사이트는 정상 개관
화면을 그린다.

임시 휴관일은 더 나쁘다. **이 문서를 쓰는 2026-09-08 현재 서울관이 임시
휴관 중이다.**

| 서울관 화요일 | 판독 | non-여유 |
|---|---|---|
| 2026-08-11 | 189 | 58 |
| 2026-08-25 | 189 | 41 |
| 2026-09-01 | 223 | 126 |
| **2026-09-08** | **1,928** | **0** |

같은 날 과천관은 166 으로 정상이다. 서울관 관람정보 페이지가
`임시 휴관일: 9월 8일(화), 12월 1일(화)` 를 명시하고 있고 실측이 정확히
일치한다. 사이트는 지금 그 관을 "여유" 로 열려 있다고 그리는 중이고,
빈 건물 판독 1,928 행이 화요일 프로파일로 들어갔다.

## 확인한 출처

관람정보 원문(2026-09-08 확인):

| 관 | 원문 |
|---|---|
| 국립중앙박물관 | `휴관일: 2026년 1월1일, 설날(2.17.화), 추석(9.25.금)` · 요일 휴관 없음 |
| MMCA 서울관 | `휴관일: 1월1일, 설날, 추석` · 요일 휴관 없음 · `임시 휴관일: 9월 8일(화), 12월 1일(화)` |
| MMCA 과천관 | `휴관일: 1월1일, 매주 월요일` · `화요일~일요일 10:00-18:00` |
| MMCA 덕수궁관 | `휴관일: 1월1일, 매주 월요일` · `화,목,금,일 10:00-18:00 / 수,토 10:00-21:00` |

관람시간은 코드의 기존 값(`LONG_CLOSE_DAYS`, 과천 18:00 고정)과 전부 일치했다.

**공휴일 월요일 예외는 어느 페이지에도 없다.** 과천·덕수궁 관람정보와 MMCA
FAQ 셋 다 `1월1일, 매주 월요일` 만 적는다. 아래 규칙 2·3 의 출처는 공식 문서가
아니라 8/17–8/18 실측 하나다. 신호 자체는 모호하지 않지만(표본이 한 번뿐인
것은 수집 기간에 공휴일 월요일이 그날 하나였기 때문이다) 근거의 성격이
다르므로 구현 주석에도 같이 적는다. **2026-10-05(월, 개천절 대체)** 는 규칙
2(공휴일 월요일 개관)를 다시 검증할 다음 기회다 — 그날 과천관에 non-빈
판독이 쌓이면 확인된다. 규칙 3(대체휴무일)은 이 계산이 배포된 뒤로는 우리
데이터로 재검증할 수 없다: 게이트가 10/06 을 닫힘으로 판정해 그날 과천관
수집 자체를 건너뛰기 때문이다 — 10/06 이 실제로 휴관인지는 이제 관 공지나
방문으로만 확인할 수 있다.

국립중앙박물관에는 **상설전시관 정기휴실일**(3·6·9·12월 첫째 월요일, 2026 년
6/1·9/7·12/7)도 있으나 관 전체 휴관이 아니고, 이 관의 데이터는 서울시
생활인구 API(그 지역 인구지 관람객 수가 아니다)라 애초에 보이지 않는다.
범위 밖으로 둔다.

## 구현 내용

### 1. 달력 — `shared/museum-holidays.json`

리포 루트에 JSON 하나. 백엔드는 파일로 읽고 프론트는 `import` 한다.

스파이크로 확인한 것(2026-09-08):

| 검증 | 결과 |
|---|---|
| `tsc --noEmit` | 통과 — `resolveJsonModule: true` 한 줄만 추가하면 됨 |
| `vitest run` | 통과 |
| `vite build` | 통과, JSON 이 번들에 인라인됨 |
| `vite` dev 서버 | `/@fs/...` 로 200 — `server.fs.allow` 를 손댈 필요 없음 |

마지막 항목이 유일하게 불확실했던 부분이다. Vite 가 `.git` 을 보고 워크스페이스
루트를 리포 루트로 잡으므로 `frontend/` 밖 파일이 기본 허용 범위에 든다.

배포에서도 성립한다 — `deploy/deploy.sh` 가 서버에서 리포 전체를 체크아웃해
(`git checkout -B main origin/main`) 프론트를 거기서 빌드하므로 두 소비자 모두
같은 파일을 본다.

```json
{
  "checkedThrough": "2027-12-31",
  "publicHolidays": ["2026-10-05", "..."],
  "closed": {
    "national-museum": ["2026-09-25", "..."],
    "seoul": ["2026-09-08", "2026-12-01", "..."],
    "gwacheon": ["2027-01-01"],
    "deoksugung": ["2027-01-01"]
  }
}
```

관 키는 백엔드 `settings.mmca_venue_space_codes` 의 키(`seoul`/`gwacheon`/
`deoksugung`)를 그대로 쓴다. 프론트 `MmcaVenue` 타입이 정확히 같은 세 값이라
양쪽에서 그대로 맞는다. 국립중앙박물관은 MMCA 가 아니므로 `venues.ts` 의
`id` 인 `national-museum` 을 쓴다.

**`publicHolidays` 에는 월요일만 적는다.** 규칙 2·3 은 "그 관의 요일 휴관일"
에서만 발동하고 그것은 월요일뿐이므로, 다른 요일의 공휴일은 판정에 닿지
않는다. 목록이 연 5개 안팎으로 줄고, 무엇보다 `holidays` 라이브러리의 회색
지대를 통째로 피한다 — 근로자의날(5/1)은 관공서 공휴일이 아니라 미술관이 정상
개관하는데 라이브러리는 공휴일로 싣고, 2027-05-03 `Alternative holiday for
Labor Day` 는 대체공휴일 제도 대상이 아닌 날에 붙은 항목이며, 제헌절(7/17)과
2027-07-19 대체는 2026 년 재지정 여부를 확인해야 한다. 월요일만 남기면 이 셋
중 2027-05-03 하나만 걸리고, 그것은 제외 대상임이 분명하다.

즉 이 파일은 **라이브러리 출력이 아니라 손으로 큐레이션한 목록**이다. 생성
스크립트를 두지 않는 이유가 그것이다.

`closed` 에는 1월 1일·설날 당일·추석 당일과 **임시 휴관일**을 함께 적는다.
임시 휴관은 관이 공지로 정하는 것이라 어떤 달력으로도 계산할 수 없다 — 아는
날짜를 손으로 넣는 것이 유일한 방법이고, 같은 경로를 쓰므로 추가 코드는 없다.

넣을 값 전체(`checkedThrough: "2027-12-31"`):

**`publicHolidays`** — 월요일 공휴일만.

| 2026 | | 2027 | |
|---|---|---|---|
| 02-16 | 설 연휴 전날 | 02-08 | 설날 둘째날 |
| 03-02 | 삼일절 대체 | 03-01 | 삼일절 |
| 05-25 | 부처님오신날 대체 | 08-16 | 광복절 대체 |
| 08-17 | 광복절 대체 | 10-04 | 개천절 대체 |
| 10-05 | 개천절 대체 | 10-11 | 한글날 대체 |
| | | 12-27 | 성탄절 대체 |

라이브러리가 월요일로 싣지만 **제외하는** 두 날: `2027-05-03`(근로자의날
대체 — 근로자의날은 관공서 공휴일이 아니라 대체공휴일 제도 대상이 아니다),
`2027-07-19`(제헌절 대체 — 제헌절의 공휴일 재지정 여부를 확인해야 한다.
확인될 때까지 넣지 않는 쪽이 안전하다. 잘못 넣으면 그날 문을 안 여는 관을
열려 있다고 그리지만, 빼면 열려 있는 관을 휴관으로 그릴 뿐이고 후자가 이미
지금의 동작이다).

**`closed`**

| 관 | 2026 | 2027 |
|---|---|---|
| `national-museum` | 01-01, 02-17(설날), 09-25(추석) | 01-01, 02-07*, 09-15* |
| `seoul` | 01-01, 02-17, **09-08**, 09-25, **12-01** | 01-01, 02-07*, 09-15* |
| `gwacheon` | 01-01 | 01-01 |
| `deoksugung` | 01-01 | 01-01 |

굵은 것이 임시 휴관일(서울관 관람정보 페이지 명시). `*` 는 음력 계산에서
나온 값으로, 미술관이 그 해 관람정보를 올리면 대조해야 한다.

### 2. 규칙 — 양쪽에 각각 ~10줄

데이터는 한 곳, 규칙은 두 곳이다. `VENUE_CLOSED_DAYS` 가 이미 그 형태이고
(주석이 서로를 가리킨다) 규칙 자체는 짧아 옮겨 적는 비용이 낮다. 값이 아니라
**목록**을 중복하는 것이 위험한 쪽이라 그것만 공유한다.

```
closed(V, D):
  1. D ∈ closed[V]                                   → 휴관
  2. D 가 V 의 요일 휴관일:
       D ∈ publicHolidays → 개관        (2026-08-17 실측)
       아니면             → 휴관
  3. D-1 이 V 의 요일 휴관일이고 D-1 ∈ publicHolidays → 휴관  (2026-08-18 실측)
  4. 그 외                                            → 개관
```

- 백엔드: `collector.py` 에 `_is_closed_day(venue, date)` 를 두고
  `_is_venue_open` 안의 요일 검사를 그것으로 바꾼다. 소비자 셋
  (`collect_mmca_once`, `health.py` 의 `_mmca_is_stale`·`_open_space_codes`,
  `scripts/purge_out_of_hours_mmca.py`)이 전부 그 함수를 지나므로 한 곳만
  고치면 따라온다.
- 프론트: `mmcaBusinessHours()` 의 `isOpenToday` 가 같은 규칙을 쓴다.
  `nextOpenDay` 는 `mmcaBusinessHours` 를 부르므로 자동으로 따라온다.
  국립중앙박물관은 `nationalMuseumBusinessHours()` 가 `isOpenToday` 를
  돌려주지 않는 형태라(요일 휴관이 없어서) 규칙 1만 붙이면 된다.

### 3. 예측 프로파일 — 손대지 않는다

게이트가 오염원을 막으면 `build_profile` 은 있는 행만 평균하므로 별도 처리가
필요 없다.

공휴일 월요일 수집이 살아나면 과천관에 "월요일 셀" 이 처음 생긴다. 평상시
월요일에는 문을 닫아 그 셀에 다른 표본이 섞일 수 없고, 프론트는 휴관일에
예측을 그리지 않으므로 그 셀은 **다음 공휴일 월요일에만** 소비된다. 다만
`PROFILE_WINDOW_DAYS = 14` 라 몇 달에 한 번인 그 표본은 대개 창 밖이고, 그러면
셀이 비어 예측선이 그려지지 않는다 — 데이터가 없으니 선이 없는 것이 맞고,
`mmca.py` 가 이미 "프로파일에 셀이 있는 시각만 나간다" 로 자기 제한적이다.
`MIN_SAMPLE_DAYS` 는 셀이 아니라 **방** 단위 게이트라 여기 관여하지 않는다.

### 4. 과거 데이터 정리

실측한 대상:

```
2026-08-18 (화, 대체 휴관)
  과천 2001·2003·2005·2007 : 48행씩 = 192행, 판독값 전부 "여유"
  과천 2002·2004·2006      : 9행씩 =  27행, 전부 null (0002 방)
  서울 1001·1006·1007      : 여유/보통/약간 붐빔 → 정상 개관, 보존
  덕수궁 4001              : 행 없음 (2026-09-02 에야 수집 대상이 됨)

2026-09-08 (화, 서울관 임시 휴관)
  서울 1,928행, non-여유 0
```

2026-08-17(개관한 공휴일 월요일) 219행은 **보존한다** — 진짜 데이터이고 규칙
2 의 유일한 증거다.

방법은 `scripts/purge_out_of_hours_mmca.py` 재실행이다. 그 스크립트가
`_is_venue_open` 을 재사용하므로 게이트를 고치면 위 날짜들이 자동으로 대상에
들어온다. 다만 지금은 `KR_HOLIDAYS` 로 공휴일을 통째로 스킵하고 있고 그
이유("달력을 못 보니 지우지 않는다")를 docstring 에 길게 적어 두었으므로,
스킵과 그 문단을 함께 걷어내야 한다.

스킵을 걷어내면 그 docstring 이 언급한 **2026-08-15(토) 과천 저녁 78행**도
대상이 된다. 영업시간 밖 행이라 원래 지워야 할 것이 맞다.

**지금 예측에는 영향이 없다** — 8/18 은 이미 14일 창 밖이다. 9/8 은 창 안이라
정리가 곧 효과를 본다. 8/18 을 지우는 이유는 백테스트와 회고 분석이다.

### 5. 달력이 낡는 문제

손으로 큐레이션한 목록이라 `checkedThrough` 를 넘기면 **조용히** 틀린다. 요일
규칙만 남아 공휴일 월요일에 휴관이라고 그리게 되고, 그것은 이 문서가 고치는
버그 그 자체다.

백엔드 테스트 하나가 `checkedThrough` 까지 60일 미만으로 남으면 실패한다.
CI 가 배포 전에 빨개지고, 고치는 방법은 JSON 에 다음 해를 채우는 것뿐이다.

대가를 분명히 해 둔다: 시간에 의존하는 테스트라 **이 변경과 무관한 PR 에서도
터진다.** 그것이 목적이다. `/health/collection` 에 필드로 노출하는 대안은
UptimeRobot 이 상태 코드만 보므로 아무도 읽지 않는다.

## 테스트

- `_is_closed_day` — 규칙 1~4 각각. 특히 2026-08-17(공휴일 월요일 → 개관),
  2026-08-18(대체 휴관 → 휴관), 2026-09-08(서울관 임시 휴관 → 휴관),
  2026-09-07(평범한 월요일 → 과천 휴관, 서울 개관).
- `collect_mmca_once` — 위 날짜들에서 부르는 방 목록이 맞는지. 특히 8/17 에
  과천 방이 대상에 들어오고 8/18 에 빠지는 것.
- `mmcaBusinessHours` / `nextOpenDay` — 같은 날짜들로 프론트 쪽 대칭 검증.
  `nextOpenDay` 가 8/17 을 "다음 개관일" 로 셀 수 있어야 한다(그 전 일요일
  8/16 에서 부르면 8/17 이 나와야 하고, 지금 규칙이면 8/18 이 나온다).
- `MmcaPage` — 임시 휴관일(9/8) 서울관에서 휴관일 안내가 뜨는지.
- 달력 만료 테스트 — `checkedThrough` 여유가 60일 미만이면 실패.
- 정리 후 재실행이 아무것도 지우지 않는지(멱등성)는 스크립트가 이미
  "a second run finds nothing left to delete" 로 보장한다.

## 알려진 한계

- **규칙 2·3 의 출처가 공식 문서가 아니라 실측 하나다.** 8/17–8/18 신호는
  모호하지 않지만 미술관이 그 정책을 공표한 적은 없다. 2026-10-05(월, 개천절
  대체)는 규칙 2(공휴일 월요일 개관)를 다시 검증할 다음 기회다 — 그날 과천관에
  non-빈 판독이 쌓이면 확인된다. 규칙 3(대체휴무일 10/06)은 이 계산이 배포된
  뒤로는 우리 데이터로 재검증할 수 없다: 게이트가 10/06 을 닫힘으로 판정해 그날
  과천관 수집 자체를 건너뛰기 때문이다 — 10/06 이 실제로 휴관인지는 이제 관
  공지나 방문으로만 확인할 수 있다.
- **설·추석 연휴가 월요일에 걸리는 충돌은 검증이 아니라 제외로 풀었다.**
  2026-02-16(월, 설 연휴 전날)·2027-02-08(월, 설날 둘째날)을 규칙 2 로 그대로
  개관 처리하면 규칙 3 이 다음날(2026-02-17 설날, 2027-02-09)을 대체 휴관으로
  닫는데, 과천·덕수궁의 공표 휴관일은 "1월1일, 매주 월요일" 뿐이라 그날 문을
  연다. 규칙 3 의 근거가 대체공휴일 한 사례(2026-08-17/18)뿐이라 연휴 월요일
  까지 늘릴 근거가 없으므로, 그 두 날짜를 `publicHolidays` 에서 뺐다 — 그러면
  둘 다 요일 휴관으로만 남아 오늘 이미 배포된 동작(월요일은 무조건 휴관)과
  같아진다. 대가는 명확하다: 대체공휴일이 아닌 그 월요일 자체는 실제로 열려
  있을 수도 있는데 하루치 수집을 계속 버린다 — 화요일을 잘못 닫는 것보다
  안전한 쪽이라 그렇게 골랐다. 2026-02-16/17 은 이미 지난 사례이고, 다음은
  2027-02-08/09 이다.
- **`closed` 의 2027 년 설·추석 날짜는 음력 계산에서 왔다**(2027-02-07,
  2027-09-15). 미술관은 해마다 관람정보 페이지에 그 해 날짜를 명시하므로,
  발표되면 대조해야 한다.
- **임시 휴관일은 사람이 공지를 보고 넣어야 한다.** 새 공지를 놓치면 오늘
  (2026-09-08) 과 같은 상황이 그대로 재발한다. 데이터로 검출하는 방법("그날
  non-여유 판독 0")이 세 범주를 전부 잡지만 사후적이고, 덕수궁관은 4001 이
  상시 0002 라 통하지 않아 이번 범위에서 뺐다.
- **국립중앙박물관 상설전시관 정기휴실일**(3·6·9·12월 첫째 월요일)은 다루지
  않는다. 관 전체 휴관이 아니고, 이 관의 혼잡도는 서울시 생활인구라 관 개폐가
  보이지 않는다.
- **`venues.ts` 의 `info.closedDays` 문자열은 그대로 둔다.** JSON 에서 뽑아
  쓰게 만들면 "1월 1일, 설날, 추석" 같은 사람이 읽는 요약이 날짜 나열로
  바뀌어 관 정보 표가 나빠진다. 두 곳이 어긋날 수 있다는 뜻이므로 주석으로
  서로를 가리킨다.

## 후속

- **2026-10-05 검증** — 규칙 2(공휴일 월요일 개관)를 다시 볼 다음 기회.
  그날 과천관에 non-빈 판독이 쌓이면 확인된다. 규칙 3(대체휴무일 10/06)은
  이 작업 배포 이후로는 우리 데이터로 재검증할 수 없다 — 게이트가 그날
  과천관 수집을 건너뛰기 때문이다. 확인하려면 관 공지나 방문이 필요하다.
  선행 조건: 이 작업 배포.
- **임시 휴관 자동 검출** — "그날 non-여유 0" 으로 `build_profile` 에서
  제외. 선행 조건: 덕수궁관처럼 판독이 전무한 관을 어떻게 다룰지 정할 것.
- **국립중앙박물관 화면의 휴관일 처리** — MmcaPage 와 같은 안내 화면.
  선행 조건: 이 작업의 규칙 1 이 `nationalMuseumBusinessHours` 에 들어갈 것.

## 배포 영향

- 신규 의존성 없음. 백엔드는 `holidays` 를 이미 쓰고 있으나 이 달력은 그것과
  별개이며, `KR_HOLIDAYS` 는 예측 배치의 `is_holiday` 피처로 계속 남는다.
- 환경변수·마이그레이션 없음.
- 배포 직후 정상적으로 달라지는 값: 휴관일에 `/mmca/*` 응답이 비고
  `/health/collection` 의 `calls_today` 가 그날 0 이 된다. `_mmca_is_stale` 이
  같은 규칙을 쓰므로 503 으로 새지는 않는다.
- 프론트 `tsconfig.json` 에 `resolveJsonModule: true` 추가.
- `scripts/purge_out_of_hours_mmca.py` 의 첫 프로덕션 실행은 **2026-10-05
  이후**로 미룬다 — 그날이 규칙 2(공휴일 월요일 개관)를 다시 검증할 다음
  기회이고, 이 스크립트의 삭제는 되돌릴 수 없다. 그 날짜보다 먼저 돌리면
  규칙이 확인되기도 전에 규칙을 사실로 놓고 지우는 셈이다.
