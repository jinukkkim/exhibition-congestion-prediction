# MMCA 과천관 전시실별 혼잡도 그래프 — 설계

- 날짜: 2026-07-26
- 배경: 국립현대미술관(MMCA) 페이지는 지금 "현재 상태만" 카드로 보여준다. 국립중앙박물관(`CongestionCard`)처럼 영업시간 전체를 그래프로 보고 싶다는 요청. 8개 전시실 중 실제로 혼잡도 값이 잘 들어오는 과천관 1전시실(`MMCA-SPACE-2001`)과 1층 어린이미술관(`MMCA-SPACE-2008`, 실제 데이터 확인 완료) 두 곳으로 먼저 검증하고, 완성 후 나머지 전시실·관에 적용한다.

## 1. 목표 &amp; 범위

**무엇을 만드나**: 과천관 페이지에서 지정한 두 전시실(1전시실, 1층 어린이미술관)을 국립중앙박물관 `CongestionCard`와 같은 크기·형식(영업시간 x축, 실시간 표시, 영업 전/후 안내)의 카드로, 화면을 절반씩 나눠 나란히 보여준다. 나머지 6개 전시실은 기존 작은 카드(`RoomCongestionCard`)로 그 아래에 그대로 둔다.

### 포함 (In Scope)

- 과천관 1전시실(`MMCA-SPACE-2001`), 1층 어린이미술관(`MMCA-SPACE-2008`) 전용 그래프 카드
- 카드 형식: 오늘 영업시간 x축, 계단형(step) 라인, 실시간 글로우 마커, "실시간"/"영업 전"/"영업 종료" 배지, 영업 외 시간엔 상태 문구만
- 과천관 페이지 레이아웃 재구성: 그래프 카드 2개(각 절반 폭) + 그 아래 나머지 6개 전시실 소형 카드 그리드
- 데이터: 기존 `GET /mmca/daily?venue=gwacheon&date=오늘` 재사용(신규 백엔드 변경 없음), 클라이언트에서 해당 전시실 하나만 필터링

### 제외 (Out of Scope, YAGNI)

- 서울관·덕수궁관, 과천관의 나머지 6개 전시실 — 이번엔 2개 전시실로만 검증. 확장은 별도 작업.
- 새 백엔드 엔드포인트 — `/mmca/daily`가 이미 관별 전 전시실 피벗 데이터를 주므로, 한 전시실만 뽑아 쓰면 충분
- 날짜 이동(이전/다음 날짜) — 이 그래프는 "오늘"만 고정 표시(국중박 `CongestionCard`와 동일). 과거 날짜 조회는 이미 있는 `MmcaDailyLogTable`이 담당
- 관별 영업시간 차이(덕수궁 월요일 휴무 등) 대응 — 과천관은 서울관과 동일한 영업시간(휴무일 없음)이라 이번 범위에서 신경 쓸 필요 없음

## 2. 데이터 &amp; 차트 형식 — 핵심 결정

**범주형 데이터를 계단형(step) 차트로**: 국중박은 연속값(인구수)이라 부드러운 곡선이 자연스럽지만, MMCA는 여유/보통/약간 붐빔/붐빔 4단계 범주형 값이다. 곡선으로 이으면 두 단계 사이를 "서서히 변한 것처럼" 보여줘 오해 소지가 있어 계단형으로 결정(값이 바뀌는 시점에만 수직으로 뚝 꺾이고, 그 사이는 평평하게 유지 — 실제로 그 시간엔 그 값이었다는 걸 정직하게 표현).

**리샘플링 불필요**: 국중박은 5분 원본을 30분 버킷으로 평균 내 스무딩한다. MMCA는 이미 15분 그리드(cron 정렬 완료, PR #24)로 수집되므로 버킷팅 없이 원본 포인트를 그대로 찍는다.

**y축**: 4단계를 순서형으로 매핑(여유=0, 보통=1, 약간 붐빔=2, 붐빔=3), 위로 갈수록 혼잡 — 국중박 차트의 "위=혼잡"과 동일한 관습 유지.

## 3. 컴포넌트 설계

### 3.1 `MmcaRoomChartCard` (신규, `frontend/src/components/`)

```tsx
{ venue: MmcaVenue; spaceCode: string; room: MmcaRoomStatus | null }
```

- `room`은 헤드라인(현재 상태 큰 글씨, 마지막 갱신 시각)에 쓴다 — `MmcaPage`가 이미 60초 폴링으로 받아둔 `fetchMmcaRooms` 결과에서 해당 `space_code`를 찾아 넘긴다(추가 fetch 없음).
- 그래프 데이터는 컴포넌트가 직접 `fetchMmcaDaily(venue, todayString())`를 호출해 받아온다(`MmcaDailyLogTable`과 같은 60초 주기 폴링). 받은 `MmcaDailyLogPoint[]`에서 `rooms.find(r => r.space_code === spaceCode)`로 이 전시실 값만 뽑고, `congestion_nm`이 `null`인 포인트(그 폴링에서 이 방만 실패한 경우)는 건너뛴다.
- 영업시간: `mmcaBusinessHours(date)` 신규 유틸(`frontend/src/lib/mmcaBusinessHours.ts`) — 10:00 오픈, 수/토 21:00 마감, 그 외 18:00 마감(백엔드 `collector.py`의 `_SEOUL_BRANCH_*` 상수와 동일한 값을 프론트에 복제). 덕수궁 휴무일 로직은 이번 범위 밖이라 포함하지 않는다.
- 라이브 판정/배지/헤드라인 전환 로직은 `CongestionCard`와 동일한 패턴(그래프 자체는 영업 전/후에도 항상 그리되, 헤드라인만 "영업 시간이 아닙니다"로 전환, 라이브 글로우 마커는 `isOpen`일 때만).

### 3.2 `mmcaBusinessHours` (신규, `frontend/src/lib/`)

```ts
export function mmcaBusinessHours(date: Date): { open: number; close: number }
```

`CongestionCard.tsx`의 `businessHours`와 같은 모양이지만 값이 다르다(10:00 오픈 vs 09:30, 마감 18:00/21:00 vs 17:30/21:00). 공유 추출은 하지 않는다 — 두 함수가 우연히 비슷해 보여도 값 자체가 도메인마다 다르고, 지금 억지로 합치면 "관별 영업시간이 또 달라질 때"(과천관 vs 덕수궁) 오히려 발목 잡는 조건분기가 늘어난다.

### 3.3 `MmcaPage.tsx` 수정

```tsx
{ venue: MmcaVenue; title: string; heroSpaceCodes?: string[] }
```

- `heroSpaceCodes`(기본값 `[]`)에 담긴 전시실은 카드 그리드에서 빠지고, 위쪽에 `MmcaRoomChartCard`로 절반씩 나란히 렌더링된다.
- 과천관 라우트(`App.tsx`)에서만 `heroSpaceCodes={["MMCA-SPACE-2001", "MMCA-SPACE-2008"]}` 전달, 서울관·덕수궁관은 그대로(빈 배열 기본값이라 지금과 동일하게 동작).
- 레이아웃: `grid grid-cols-1 lg:grid-cols-2 gap-6` 컨테이너에 히어로 카드 2개, 그 아래 기존 `grid sm:grid-cols-2 lg:grid-cols-4`에서 `heroSpaceCodes`에 속하지 않는 방만 필터링해 렌더링.

## 4. 데이터 흐름 &amp; 에러 처리

- `MmcaRoomChartCard`는 `fetchMmcaDaily` 실패 시 그래프 없이 헤드라인만(기존 `room` prop 기준) 표시 — `MmcaDailyLogTable`과 동일하게 조용히 재시도, 화면이 비지 않도록 함.
- 오늘 데이터가 아직 없을 때(예: 영업 시작 직후)는 빈 배열 → 그래프 영역은 "실시간" 배지 아래 빈 상태로, 헤드라인은 `room` prop이 있으면 그 값 그대로 표시(카드가 통째로 안 사라짐).

## 5. 테스트

- `MmcaRoomChartCard.test.tsx` 신규: 로딩/영업 전·후 문구 전환, 계단형 path 렌더링(`data-testid`), 라이브 마커가 `isOpen`일 때만 나오는지, `congestion_nm`이 null인 포인트를 건너뛰는지 — `CongestionCard.test.tsx`의 구조(고정 시각 `vi.setSystemTime`)를 그대로 따른다.
- `MmcaPage.test.tsx`: `heroSpaceCodes` prop을 줬을 때 해당 방이 소형 그리드에서 빠지고 히어로 카드로 렌더링되는지, prop 없을 때(서울관/덕수궁관) 기존 동작 그대로인지.
- e2e: 과천관 페이지 방문 시 히어로 카드 2개 + 나머지 6개 소형 카드 렌더링 확인 한 줄 추가.
